# TeamFightMange2-mod

> **永恩 W 的存档最低版本仍是 `0.10.5`。** 旧 E 存档和 `0.10.4` 矩形 W 存档只会通过无行为兼容入口安全加载；验证当前 W 必须使用在 `0.10.5` 或更高版本中新建的存档。已经在 `0.10.5` 新建且包含当前 W 的存档升级到 `0.10.7` 后不需要再次新建。

## v0.10.7：永恩人物模型从零重做

- 废弃 `0.10.6` 中脸部过小、身体像素分散的 V4 人物。新的 V5 金样直接面向 `43×55` 原生待机帧制作：人物有效轮廓为 `30×38`，连续脸部为 `8×10`，主躯干保持密实连接；真实 `141×138` 卡片路线中脚底距分隔线 `8px`，且不覆盖右侧 UI。
- 移动、普攻/Q/W、R 分成三套同模型 ImageGen 动作源，错误的断臂 Q 帧使用独立完整来源替换。源阶段一次性生成全部 `54` 张最终原生尺寸、硬 alpha、最多 `32` 种不透明颜色的 RGBA 身体帧；图集打包只逐字节复制，不再对人物重复缩放或回退 V4。
- 物理删除 V4 人物帧、两张旧身体源、旧生成器、旧 validator 和旧 schema，并把这些路径加入退役检查。Q/W/R 技能逻辑、独立特效、图标和音频保持不变。
- 保留旧 E 与旧矩形 W 的无行为存档兼容入口，避免旧内嵌技能树在 BP 后崩溃；它们不会恢复 E，也不会迁移成当前 W。

## v0.10.6：永恩原生逐帧视觉重制（失败历史，已被 v0.10.7 取代）

- 一张新的成年比例 ImageGen 动作表只作为统一造型与动作身份源，不直接作为战斗图集，也不在打包阶段反复缩放。源阶段生成器从它输出全部 `54` 张精确原生尺寸 RGBA 身体帧；每张帧固定硬 alpha、最多 `32` 种不透明颜色，并在进入图集前完成尺寸、调色板和像素身份校验。
- `idle[0]` 的脸部在官方 `43×55` 原生帧内逐像素锁定主眼、弱化远眼、鼻、嘴、下颌与左后侧小型亚扎卡纳面具。图集构建只逐字节复制已验收的原生帧，不再裁切、缩放、量化、回退旧人物或在打包阶段补画脸、手臂和武器。
- CI 复现真实 `141×138` 卡片路径：原生 `idle[0]` 使用 `NEAREST` 放大并居中，脚部与武器距黑色分隔线至少 `6px`，右侧 UI 图标安全区与人物 alpha 重叠为 `0`。这道门同时约束脸部可读性、脚底位置和右侧图标遮挡。
- 当前默认运行时的对局 actor、BP 英雄卡和比分板头像都来自同一 actor idle 路径；不能依赖默认关闭的 base `0.5.0` 旧 client extension，也不能把未被默认路由的独立 `ui/champion_portrait/*` 或 `ui/champion_fullbody/*` PNG 当作实机修复证据。
- v0.10.5 使用的四套 V3 身体 contact、其处理后副本和 native body master 已清退；Q/W/R 独立特效、技能数据与 `0.10.5` 存档合同不变，因此已有有效 `0.10.5` W 存档可直接升级验证本次视觉更新。

> 本节保留 `0.10.5` 的 W 技能与存档合同。其四套 V3 ImageGen 身体 contact 和整表栅格化人物路线已经由 `0.10.6` 的 54 张精确原生 RGBA 帧路线取代，不能再用作当前人物视觉验收标准。

- 兼容入口只负责让旧 E / `0.10.4` 矩形 W 存档不因退役原生效果名而在 BP 后闪退。它们不会重写存档内嵌技能树；在 `0.10.5` 或更高版本中新建的存档才会获得上述锥形 W。`0.10.6` 只更新人物视觉，不要求已有有效 `0.10.5` W 存档再次新建。

## 构建与测试

```powershell
python -m pip install -r .\requirements-dev.txt
powershell -ExecutionPolicy Bypass -File .\mods\lol_mod\tools\build_native_dll.ps1
python .\mods\lol_mod\tools\build_lol_mod.py --rebuild-quality
python .\mods\lol_mod\tools\validate_lol_mod.py

```
